## Lessons Learned & Gotchas
- `-c.productName="NEO MCP"` only renames the bundle and executable. Electron's userData follows the packed package.json `productName` (`NEO`). Changing that would orphan `settings.json` (`mcp.port` 47811) and `secrets.json` (`mcp-token`), and break Claude Code's `neo` server config.
- NEO MCP and a stock NEO install share the same userData folder and library. Not tested whether both can run at once.
- electron-builder warns that ad-hoc signing with hardenedRuntime needs `com.apple.security.cs.disable-library-validation`; `build/entitlements.mac.plist` already has it, and the app launched fine.
- Claude Code's `neo` MCP is stdio via `scripts/mcp-stdio.js` with `NEO_MCP_TOKEN` in env (in `~/.claude.json`). The app must be running with Show More Features on and the server enabled, or the stdio bridge reports NEO isn't answering.
- E2E tests (`npm run test:mcp`, `test:simple`, `test:words`) run in Electron and take tens of seconds each; unit tests take about 3.5 s.
- `dist/` is gitignored; each build overwrites `dist/mac-arm64`.
